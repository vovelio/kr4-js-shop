## Что сделано по пунктам

1. Практика №15: создан отдельный проект `kr4-js-shop`, подключены JS-файлы с `defer`. Объект первого товара и результаты функций выводятся в консоль. На главной и в каталоге есть учебный блок с результатами через `textContent`.
2. Реализованы `formatPrice`, `calculateDiscount`, `calculateFinalPrice`, `getProductStatus`, `createProductSummary`: форматирование рублей, сумма скидки, цена после скидки, наличие и строка описания.
3. Практика №16: массив из 8 товаров, единая структура `id`, `title`, `category`, `price`, `discountPercent`, `rating`, `isAvailable`, `image`. В №16 минимум 6, в итоговой №18 минимум 8–12, поэтому в проекте 8.
4. Реализованы получение названий, выбор доступных товаров, поиск, категория, сортировка копии массива, поиск по id, сумма исходных цен, количество доступных товаров и средняя исходная цена. `getPreparedProducts` объединяет поиск, категорию и сортировку.
5. Практика №17: карточки каталога строятся через `document.createElement`, `classList`, `append` и `textContent`. При вводе поиска или изменении категории/сортировки каталог строится заново. Есть счётчик и пустое состояние.
6. Существующая форма заявки проверяется на обязательность, длину имени от 2 символов, e-mail, телефон из 11 цифр и согласие. Ошибки выводятся под полями, первое неверное поле получает фокус. На успешное заполнение выводится сообщение. На сервер ничего не отправляется.
7. Практика №18: проверяется базовая часть КР №4, готовится итоговый репозиторий. React/Vue из второй части №18 относится к следующей КР №5 и здесь не используется.

Корзина, localStorage, избранное и тёмная тема не добавлялись. Это базовый вариант по запросу, который по шкале №18 оценивается максимум в 4 из 8 баллов.

## Безопасный вывод

`textContent` вставляет обычный текст, а не HTML. Поэтому строка, похожая на HTML-тег, не выполняется как разметка. `innerHTML` для пользовательских данных не используется. Изображения берутся из локального массива проекта.

## Как проверить и защитить

1. Открыть `index.html`, затем Console: показать объект, функции и массив.
2. Открыть каталог: должно быть 8 карточек. Ввести «пенал»: останутся два. Проверить поиск с пробелами и другим регистром.
3. Выбрать категорию, переключить сортировку. Поиск и категория действуют вместе. Сортируется копия массива, исходные данные сохраняются.
4. Ввести отсутствующий товар: показать «Товары не найдены» и счётчик 0.
5. Открыть заявку, отправить пустую: показать текстовые ошибки. Проверить короткое имя, неверный e-mail, телефон и согласие, затем заполнить правильно.
6. В DevTools → Sources поставить breakpoint на первой строке `updateCatalog`, изменить поиск и посмотреть значения полей и вызов `getPreparedProducts`; затем продолжить выполнение. Аналогично проверить submit в `validation.js`.
7. Объяснить: `input` — ввод текста, `change` — изменение выбора, `submit` — отправка формы. `preventDefault()` отменяет перезагрузку/отправку.
8. `defer` выполняет скрипты после разбора HTML, в порядке подключения: данные → функции каталога → формы → общие действия.
9. В Console можно вызвать `calculateDiscount(2500, 20)` (500), `calculateFinalPrice(2500, 20)` (2000), `findProductById(products, 1)`.

Запуск: открыть `index.html` или выполнить `python3 -m http.server 8000` в папке проекта и открыть `http://localhost:8000`.
